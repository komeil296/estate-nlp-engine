# معماری Estate NLP Engine

## اصل معماری

موتور NLP مستقل از اپلیکیشن موبایل، CRM، سرور و ارائه‌دهنده مدل است. ورودی متن فارسی می‌گیرد و خروجی ساختاریافته و قابل اعتبارسنجی تولید می‌کند. نسخه اول باید بدون اینترنت و GPU قابل اجرا باشد.

## خط پردازش فعلی متن

```text
Raw Persian Text
      |
      v
Normalization
      |
      v
Rule-based Extractors
  |       |       |
  |       |       +--> Rental Conditions
  |       +----------> Financial Mentions
  +------------------> Transaction / Property / Areas / Rooms / Features
      |
      v
Typed Domain Models
      |
      v
JSON Schema Validation
```

پیاده‌سازی فعلی در `src/estate_nlp/` قرار دارد:
- `normalization.py`: یکسان‌سازی نویسه‌های عربی/فارسی، ارقام، فاصله و کنترل‌های جهت متن.
- `extractor.py`: استخراج اولیه نوع سند، معامله، ملک، متراژ، اتاق، ویژگی‌های بولی و اجازه اجاره به مجرد.
- `financial.py`: استخراج مبلغ‌ها، نقش مالی، ارز و دوره؛ بدون تبدیل خودکار ریال/تومان.
- `models.py`: مدل‌های تایپ‌شده و وضعیت‌های `extracted`، `not_found`، `ambiguous` و `conflict`.
- `divar_dataset.py`: نگاشت metadata و برچسب‌های ساختاریافته منبع Divar به weak labelهای قابل ردیابی. این مسیر از استخراج متن جداست.

## مسیر داده و آموزش آینده

```text
Divar SQLite (read-only source)
          |
          v
Metadata Audit + Source Label Mapping
          |
          v
Weak Labels + Original Source Values
          |
          v
Human Review / Gold Annotation
          |
          v
Train / Validation / Test Dataset
          |
          v
Future Lightweight Model (optional)
```

نگاشت منبع، حقیقت قطعی تولید نمی‌کند. مقدارهای ساختاریافته ممکن است در متن تکرار نشده باشند یا با متن اختلاف داشته باشند. متن خام، متن نرمال‌شده، برچسب منبع، خروجی استخراج و برچسب تأییدشده باید جدا نگهداری شوند.

## ارزیابی

اسکریپت `scripts/evaluate_divar_extractor.py` نمونه‌ای تصادفی و طبقه‌بندی‌شده از هر دسته انتخاب می‌کند و توافق استخراج‌گر با برچسب‌های منبع را اندازه می‌گیرد. این عددها precision/recall طلایی نیستند. برای ادعای کیفیت نهایی باید مجموعه طلایی با بازبینی انسانی ساخته شود.

## محدودیت‌های فعلی

- استخراج مکان از متن هنوز پیاده‌سازی نشده است.
- بیشتر جزئیات ساختمان مانند طبقه، سال ساخت، جهت و نوع سند هنوز از متن استخراج نمی‌شوند.
- ویژگی‌های گرمایش، سرمایش و سرویس بهداشتی در دیتاست منبع چندحالته‌اند؛ خروجی فعلی آن‌ها را فقط به‌صورت boolean ساده پوشش می‌دهد و باید در نسخه بعدی غنی شود.
- parser مستقل اعداد نوشتاری فارسی هنوز وجود ندارد.
- ساخت دیتاست آموزشی نهایی، تقسیم train/validation/test و gold annotation هنوز انجام نشده است.
- اپ موبایل، CRM، سرور و همگام‌سازی در این مخزن پیاده‌سازی نشده‌اند.

## اجرای آفلاین

هسته فعلی از کتابخانه‌های استاندارد Python و قواعد محلی استفاده می‌کند. هیچ API خارجی یا تماس شبکه‌ای در مسیر استخراج لازم نیست.

## اصل ایمنی داده

داده آگهی حقیقت قطعی ملک نیست و ممکن است ناقص، تبلیغاتی، مبهم یا نادرست باشد. هیچ فایل دیتابیس یا متن خام واقعی نباید بدون بررسی مجوز و حریم خصوصی وارد Git شود.
