# معماری اولیه

## اصل معماری
موتور استخراج باید مستقل از اپلیکیشن موبایل، CRM و ارائه‌دهنده مدل هوش مصنوعی باشد. ورودی متن و خروجی ساختاریافته داشته باشد و بتوان آن را در محیط محلی یا سرور اجرا کرد.

## خط پردازش پیشنهادی
```
Raw Persian Text
      |
      v
Normalization
      |
      v
Tokenization / Number Parsing
      |
      v
Dictionary + Pattern Matching
      |
      v
Rule Engine + Context Resolution
      |
      v
Structured Output + Confidence + Evidence
```

این نمودار طرح پیشنهادی است و هنوز پیاده‌سازی نشده است.

## خروجی استخراج
خروجی باید علاوه بر مقدار استاندارد، شواهد متنی و وضعیت اطمینان را نگه دارد. نمونه مفهومی:

```json
{
  "property_type": {
    "value": "villa",
    "evidence": "ویلای",
    "confidence": 0.98
  },
  "building_area_sqm": {
    "value": 250,
    "evidence": "۲۵۰ متر بنا",
    "confidence": 0.93
  }
}
```

نمونه بالا قرارداد نهایی داده نیست؛ فقط ایده خروجی را نشان می‌دهد.

## تفکیک مسئولیت‌ها
- Normalizer: یکسان‌سازی نویسه‌ها، فاصله‌ها و شکل عددها بدون حذف متن خام.
- Number Parser: تبدیل اعداد فارسی/عربی/لاتین و عبارت‌های عددی نوشتاری.
- Lexicon: واژگان، مترادف‌ها، گونه‌های محاوره‌ای و اصطلاحات ملکی.
- Extractors: استخراج موجودیت‌های مشخص مانند متراژ، قیمت، اتاق و موقعیت.
- Rule Engine: تفسیر وابسته به بافت و حل تعارض قواعد.
- Dataset Builder: ساخت نمونه‌های قابل برچسب‌گذاری و ارزیابی.
- Evaluation: محاسبه معیارهای کیفیت روی داده مرجع.

## اجرای آفلاین
نسخه اول باید بدون تماس شبکه‌ای قابل اجرا باشد. وابستگی‌های خارجی و مدل‌های ابری در هسته استخراج قواعدمحور قرار نمی‌گیرند.

## نکته مهم
داده آگهی‌ها به‌تنهایی حقیقت قطعی ملک نیستند؛ ممکن است متن ناقص، تبلیغاتی، مبهم یا نادرست باشد. موتور باید «آنچه متن ادعا می‌کند» را از «واقعیت تأییدشده ملک» جدا نگه دارد.
